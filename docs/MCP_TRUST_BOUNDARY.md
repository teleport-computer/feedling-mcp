# 用户自建 MCP 的信任边界

> 2026-08-12 Seven 拍板。**这份文档是给「想把围栏加回去的人」看的** ——
> 代码里几处注释指向这里。加回去之前请先读完,尤其「为什么当初有」那一节。

## 当前立场

**用户自己配置的 MCP 服务器,按用户自己的基础设施对待,不按「模型自己搜到的
外部内容」对待。** 全面对齐 Claude Code。

| | 我们 | Claude Code |
|---|---|---|
| 工具描述 | 原样透传 | 原样透传 |
| 工具命名 `mcp__<server>__<tool>` | 有 | 有 |
| 服务器 `instructions` 进系统提示 | 有 | 有 |
| 工具输出包「不可信」壳 | 无 | 无 |
| 看过 MCP 返回后禁用 MCP | **已拆** | 无 |
| 读过私密内容后禁用 MCP | **已拆** | 无 |

仍然保留的:

- `mutation_outcome_unknown` → 禁后续**变更类** MCP 工具。
  防的是远端超时后可能已提交、再写一次会重复 —— **幂等性,不是信任**。
- web / task 的出站围栏原样保留。那是**模型自己选的目的地**;MCP 是**用户挑的**。
- 网络层全部保留:SSRF(DNS/IP 必须是全球单播)、拒重定向、超时、响应大小上限、
  拒压缩响应。这些防的是服务器行为异常,不是内容可信度。

## 为什么当初有(别把这段读成「所以该加回去」)

原设计的推理是成立的:每次 MCP 调用都跨出站边界,如果前一次的返回内容能操纵
后一次请求的参数,模型就可能把用户的私密记忆当参数发出去。这是教科书式的
prompt-injection exfiltration 链。

**它错在把「威胁模型」搞混了。** 模型自己搜到的网页,用户从没见过、也没选择过;
而 MCP 服务器是用户自己找的地址、自己填的鉴权头、自己点的保存。后者更接近
「用户自己的数据库」,不是「互联网上的随便一个页面」。

## 代价有多大(为什么必须拆)

- **一轮只能调一次 MCP**。记忆型服务器(Ombre Brain 之类)的标准用法是开场取
  记忆、聊完存回去 —— 第二步必然失败。用户报的是「MCP 只能读不能写」。
- **更隐蔽的那条**:`_PRIVATE_READ_TOOLS` 里有 `memory_index/search/fetch`,
  而模型几乎每轮都读记忆。于是 MCP 常常在第一次调用**之前**就没了。
  用户看到的是「App 里显示已连接,AI 却说用不了」——查了整整一天才定位到。

## 被接受的风险面(说清楚,别装作没有)

模型读过用户私密记忆后,可以把内容作为参数发给**用户配置的任意** MCP 服务器。
包括论坛这类**别人可写内容**的服务器 —— 我们见过真实用户同时配了记忆库和论坛。

Seven 明确接受该风险,理由是:服务器是用户自己挑的,产品不该替用户决定他能不能
把自己的数据发给自己选的地方;而围栏的代价是功能直接不可用。

## 如果将来要收回来

不要整条加回去。可行的中间形态(2026-08-12 讨论过但因为「一个开关解决三件事」
过于耦合而没做):**逐台标记「记忆源」**,标记的不受围栏限制、未标记的维持保护。
真要做的话,标记必须默认关、逐台勾,并在 UI 上写明「只勾你自己控制的服务器」。
