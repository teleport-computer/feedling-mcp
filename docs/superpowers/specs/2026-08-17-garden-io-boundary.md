# Garden / io 边界：什么该进独立库，什么必须留在 io

> 2026-08-17。开源前必须回答的问题。
> 现在的划分是**提取时顺手划的，不是想清楚划的** —— 本文是把它想清楚。

---

## 一、判断标准（先定尺子，再分东西）

一句话：**「换个宿主还成立吗？」**

```
成立    → 进 garden      「一张卡只讲一件事」「同一件事别写两遍」
不成立  → 留 io          「io 的伴侣叫什么」「卡怎么加密」「谁触发」
```

三个更细的判据，按优先级：

| # | 问题 | 是 → | 
|---|---|---|
| 1 | 它需要网络 / 数据库 / 密钥吗？ | 留 io（内核是纯函数） |
| 2 | 换个产品还有意义吗？ | 有 → garden；没有 → io |
| 3 | 别人会想改它吗？ | 会 → garden，但要做成**可配置**，不是写死 |

第 3 条是最容易漏的。**在 garden 里写死一个 io 专用的值，比放在 io 里更糟** ——
放 io 里别人看不见，写死在 garden 里别人会继承它还不知道为什么。

## 二、现状盘点（2026-08-17 实测）

### ✅ 划对了的

```
policies.py          三个档位（少而厚 / 滤一次性事件 / 全留）
text/                卡片文本规范：不许占位符、不许协议残片、一张卡讲一件事
dreaming.py          该不该整理一次：种子卡计数、快照签名、幂等键
storage.py           存储接口 + 能力声明 + 降级说明
card_fields.py       字段映射（已做成可替换的 FieldMap）
scoring/relevance.py 相关性打分算法本身
```

这些换个宿主都成立。

### ❌ 划错了的：在 garden 里，但其实是 io 的产品决策

#### 1. 分桶挑法的 3 / 2 / 3（`scoring/relevance.py:479-509`）

```
3 张转折卡 + 2 张最近 + 3 张相关，cap 8
```

这是 io 陪伴产品 2026-05 的设计。**别人拿到包会连它一起继承**，
而且转折卡靠标题前缀 `转折｜` 识别 —— 对别人完全无意义。

**怎么办**：做成 `SelectionPolicy` 值对象（与 `card_fields.FieldMap` 同套路），
默认实例是 io 现在这套，外部传自己的。

#### 2. 提示词正文是中文（`prompts/*.py`、`policies.py`）

`buckets.py` 23 处、`policies.py` 21 处中文表述。
**一个满是中文提示词的库，外国人装上就废了。**

这条已在 handoff 里标为"对外开源前必须解决"，这里再钉一次：
它不是文案问题，是**能不能开源**的问题。

**怎么办**：提示词模板与语言分离，或提供 `locale` 参数。范围不小，要单独立项。

#### 3. 桶名是中文且写死（`prompts/buckets.py`）

「工作 / 健康 / 我们的关系 / 未分类」—— 这是 io 的产品分类法。
别人的场景可能是「项目 / 客户 / 决策」。

**怎么办**：同样做成可配置，默认给 io 这套。

### ⚠️ 边界正确但描述含糊的

```
types.py 里的 source 枚举（16 种）
   genesis_import / resident_absorb / model_api_capture / ombre_brain_sync …
   —— 全是 io 的来源名。别人只需要「这张卡打哪来」这个概念，不需要这 16 个值。
```

**怎么办**：内核只认「来源」是个字符串标签，具体取值由宿主定。

## 三、必须留在 io 的（这些不要往 garden 搬）

```
加解密           信封、K_enclave、AAD 绑定、enclave 解密
                 —— 内核连密文长什么样都不知道，这是刻意的

什么时候触发     20 分钟静默、夜间窗口、失败退避、最小间隔
                 —— 宿主的调度策略，不是记忆的判断

身份与称呼装配   identity 卡、用户画像、相处风格
                 —— 但「卡里别叫用户」这条规则已搬进 garden（naming.py），
                    因为它讲的是「卡该怎么写」

存储实现         数据库、多租户、迁移
                 —— garden 只出接口

候选池大小       50 / 200 的窗口
                 —— 宿主根据自己的数据规模定
```

## 四、一条容易越界的灰色地带

**observability.py**（2026-08-17 新增）算 garden 还是 io？

结论：**garden**，但只放"把挑卡过程压成内容无关记录"这一层。
理由：什么算"卡片内容"是 garden 的知识（它定义了字段映射），
而**怎么落库、发到哪、谁来存**是 io 的事。

现在的实现就是这么分的：garden 出记录，io 负责落库。

## 五、开源前的必办清单

按阻塞程度排序：

```
🔴 提示词中文化       不解决就没法给外国人用
🔴 桶名可配置         同上，且改动比提示词小
🟠 挑卡规则可配置     否则别人继承 io 的 3/2/3 还不知道为什么
🟠 source 枚举去 io 化  改成开放标签
🟡 转折卡识别         靠标题前缀本来就脆弱，顺带改成显式语义字段
```

> ⚠️ 前两条是**能不能开源**的问题，后三条是**开源后好不好用**的问题。
> 别把它们混成一批做。
