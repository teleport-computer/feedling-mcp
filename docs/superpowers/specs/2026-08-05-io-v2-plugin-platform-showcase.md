# IO V2：让用户决定自己的 IO 拥有什么能力

> Showcase 简版｜建议讲述时长：3–5 分钟

## 一句话

IO V2 会把 Identity、Memory Garden、iOS Perception、Inner Thought 从默认捆绑的功能，变成用户可以自主开启和停用的官方插件。

用户开启什么，IO 才拥有什么；用户关闭什么，它就真正停止。

## 为什么要做

现在的 IO 已经能记忆、形成身份、感知设备情境，也能在后台思考和主动出现。

但这些能力被装在同一个整体里。用户很难清楚回答：

- IO 现在开启了哪些能力？
- 每项能力会读取什么？
- 我关闭它以后，它是否真的停止？
- 我能不能只要记忆，不要后台主动思考？

V2 首先解决的不是“让 IO 更强”，而是让用户更有掌控感。

## V2 会变成什么

IO 被拆成两层。

### IO Core

Core 始终提供账户、模型连接、安全和基础聊天。即使关闭全部插件，用户仍然可以正常与 IO 对话。

### 官方插件

| 插件 | 为 IO 增加什么 |
|---|---|
| **Identity** | 稳定的人格、关系理解、称呼和表达偏好 |
| **Memory Garden** | 形成、保存和找回长期记忆 |
| **iOS Perception** | 在授权范围内感知屏幕、位置、运动、日历等情境 |
| **Inner Thought** | 在后台整理想法，并在真正有价值时主动出现 |

新用户会看到 Identity + Memory Garden 的推荐组合；感知和后台思考则分别说明权限，由用户自主决定是否开启。

## 用户会看到什么

V2 增加一个统一的“插件中心”。

每个插件都会清楚说明：

- 它能带来什么；
- 它需要访问什么；
- 为什么需要这些权限；
- 停用后会发生什么。

停用插件不会删除数据，但会立即停止新的读取、写入、上下文注入、后台任务和主动消息。重新开启后，原有数据仍然存在。

用户只负责选择能力，不需要搭工作流，也不需要决定插件执行顺序。

## 它如何真正做到“关闭”

V2 不会只增加几个 UI 开关。

Core 中会新增统一的 **Capability Host**。所有插件读取数据、贡献上下文、处理事件、运行后台任务或发送消息，都必须经过它检查：

```text
事件进入
  → 插件是否启用
  → 用户是否授权
  → 当前预算是否允许
  → 插件执行
  → 产物再次检查
  → 写入或发送
```

检查会发生两次：执行前一次，提交结果前再一次。

因此，即使用户关闭 Inner Thought 时有一个后台任务正在运行，它稍后返回的结果也不能继续写入记忆或给用户发消息。

## 插件如何组合

插件有两种关系：

- **必需依赖**：缺少时不能运行，系统会提示连带开启；
- **可选增强**：存在时体验更好，不存在时正常降级。

例如，Inner Thought 不强制依赖 Identity 或 Memory Garden。用户可以只开启后台思考；如果同时启用身份和记忆，它会获得更连贯的上下文。

iOS Perception 也可以独立开启，用于用户主动提问时理解当前情境，而不必同时开启后台思考。

## 怎么落地

V2 分四步推进：

1. **搭能力宿主**：定义插件说明、权限、状态、依赖和标准事件。
2. **逐个收口能力**：按 Identity、Memory Garden、iOS Perception、Inner Thought 的顺序接入统一权限闸门。
3. **上线用户控制面**：发布插件中心、授权说明、推荐组合和启停入口。
4. **全量强制**：确认旧链路没有旁路后，正式启用权限强制并清理旧实现。

现有用户升级后保持原有行为。系统会根据当前实际启用状态生成插件授权，并在首次进入插件中心时展示迁移摘要，不会要求用户从头配置。

## 首版刻意不做什么

首版只验证四个官方插件，不做插件市场、第三方代码执行、自定义工作流、独立插件部署或复杂活动日志。

但 manifest、权限、事件、数据域和生命周期会从第一天形成稳定协议，为未来开放第三方插件留下接口。

## 怎样算成功

V2 成功的标准不是“页面上出现了插件开关”，而是：

- 关闭所有插件，纯聊天仍然可用；
- 任意插件停用后，相关行为真正归零；
- 用户能用自己的话说明每个插件做什么、访问什么；
- 四个插件可以自由组合，彼此不会暗中绑定；
- 新增官方插件时，不需要修改其他插件的内部实现。

## 收尾

IO V2 想建立的是一条简单而可信的产品规则：

> **能力属于用户选择，不属于产品默认。**

这会让 IO 从一个固定形态的 Personal Agent，变成一个用户可以理解、信任并逐步组装的个人智能系统。
