# Prod Backend Gunicorn Worker 12 小时生命周期观测报告

**观测日期**：2026-08-29

**观测窗口**：02:15:57–14:17:49 CST（约 12 小时）

**环境**：prod backend CVM

**对象**：1 个 Gunicorn master、6 个 Gunicorn worker

**报告性质**：只读观测记录，不是事故定性或根因报告

---

## 1. 摘要

本次连续观测记录了 prod backend 6 个 Gunicorn worker 的 PID 轮换，共得到
**50 个已完成的 worker 代际**。观测结束时仍存活的 6 个 worker 属于右删失样本，
未计入完整寿命统计。

已完成代际的中位寿命为 **82.6 分钟**，P90 为 **116 分钟**。50 个样本中，
35 个（70%）在 60–120 分钟内结束；同时存在明显长尾，最长样本约为
816 分钟（13.6 小时）。

观测期间 Gunicorn master PID 始终为 `1647`，未观察到 backend 容器整体重启；
worker 池在每次轮换后均保持 6/6。观测终点公开 `/healthz` 返回 HTTP 200，
状态为 `healthy`。

## 2. 观测目的

单次 health 请求只能返回命中 worker 的当前 uptime，无法回答以下问题：

- 一个 worker 从启动到退出实际存活多久；
- 6 个 worker 是否均匀轮换；
- PID 变化来自 worker 独立回收，还是 Gunicorn master 或容器整体重启；
- 多个 worker 是否会在较短时间内集中回收。

本次观测只收集上述事实，不对业务故障、用户影响或后续改动做定性。

## 3. 观测配置与方法

观测时 backend 的 Gunicorn 配置包括：

```text
workers = 6
max_requests = 50000
max_requests_jitter = 25000
graceful_timeout = 120
keepalive = 75
```

采样约每分钟读取一次 backend 容器中的进程信息：

```text
PID / PPID / ELAPSED / RSS / COMMAND
```

统计口径如下：

1. master 的直接子进程记为 worker；
2. worker PID 消失且出现新 PID，记为一次代际结束和一次新代际开始；
3. 新 worker 的出生时间由采样时间减去 `ELAPSED` 推算；
4. 旧 worker 的退出时间以替代 worker 的出生时间近似；
5. 超过一小时后，`ELAPSED` 只显示到分钟，因此相应寿命存在约 ±1 分钟误差；
6. 同一采样窗口内同时替换多个 worker 时，若无法唯一对应新旧 PID，只保留该组
   寿命范围，不强行指定映射；
7. 观测结束时仍存活的 worker 不作为完整寿命样本。

直接平均值受到 205.2 分钟和 816 分钟两个长尾样本的明显影响，因此中位数和

| 寿命区间 | 数量 | 占比 |
|---|---:|---:|
| 小于 60 分钟 | 10 | 20% |

50 个完整代际中有 35 个（70%）位于 60–120 分钟区间。

### 4.2 按轮换速率换算

12 小时内共观察到 50 次 worker 退出：

```text
整个 6-worker 池：50 / 12 ≈ 4.17 次回收/小时
按 6 个 worker 换算：6 / 4.17 × 60 ≈ 86.4 分钟/worker
```

该换算值与 82.6 分钟的样本中位数接近。它描述的是本次观测窗口的总体轮换速率，
不是单个 worker 的固定寿命。

## 6. 进程连续性

观测期间：

- Gunicorn master PID 始终为 `1647`；
- 未观察到 master uptime 归零；
- 未观察到 backend 容器整体重启；
- 每次 PID 变化均表现为一个或少量 worker 被新 worker 替代；
- 每轮替换后都能再次观察到 6 个 worker。

因此，本报告记录到的 PID 变化属于 worker 级轮换，不是容器级重启记录。

## 8. 观测结论

本次 12 小时窗口内可以直接确认：

1. worker 的典型完整寿命约为 83–86 分钟；
2. 多数完整寿命位于 60–120 分钟，但样本存在明显长尾；
3. 多个 worker 在相近时间轮换的情况多次出现；
4. PID 轮换期间 master 保持连续，worker 池维持 6/6；
5. 观测终点服务健康。

本报告不能仅凭进程采样确认每次退出的内部触发原因，也没有记录每个 worker 的累计
请求数、退出码或 Gunicorn 回收日志。因此，它描述的是 worker 生命周期和轮换分布，
不对每次轮换的具体原因作进一步判断。
